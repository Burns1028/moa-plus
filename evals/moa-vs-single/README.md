# 单 Agent 与 MoA+ 对照评测

这套评测检查默认 MoA+ 是否在任务质量、等待时间和模型用量上带来可观察的收益。
它使用真实模型和原生 DSH Agent Loop；不使用脚本模型，也不在题目里要求创建助手或启用验收。

## 题目与评分

| 类别 | 任务 | 主要检查 |
| --- | --- | --- |
| 简单 | 简短确认 | 精确、简短交付 |
| 简单 | 计算与一句解释 | 数值、指定计算方法、长度 |
| 代码 | CSV 修复 | 引号、换行、空字段、错误和往返 |
| 代码 | 用量账单 | 去重、分层计价、抵扣、税额、模块集成 |
| 代码 | 增量构建与 CLI | 依赖闭包、拓扑波次、变更传播和错误契约 |
| 分析 | 分片交易对账 | 时间边界、重复、退款、分区和逐订单明细 |
| 分析 | 故障材料调查 | 影响、重试、因果证据、竞争假设和未知事实 |
| 分析 | 版本化规则 | 版本日期、例外范围、限制优先级和每条决策 |

另有独立难题组（`--suite hard`）：并发缓存的订阅取消、LRU/TTL与迟到结果，以及多模块事务账本的原子持久化、幂等去重与恢复。它们不混入默认基础集的结果。每题的完整契约和公开测试均提供给模型，隐藏检查覆盖交错执行和失败路径。

每题满分 100，采用隐藏的确定性检查，不用额外模型主观评分。题目所需契约全部提供给被测模型；隐藏的是测试样例和参考结果。
代码评分直接运行产物接口及 CLI，带子进程超时；分析评分核对 JSON 结果、金额、集合和证据。分析任务修改输入违反明确要求，该次计零分。
超时仍检查已存在产物并保留部分得分，正常结束和满分交付分别统计。

`suite.mjs` 组合题目。`cases-code.mjs` 和 `cases-analysis.mjs` 中只有 `files` 与 `prompt` 会提供给模型；评分代码留在工作目录外。
评分源码没有提供给模型，并不代表操作系统禁止读取目录外的一切文件。

## 对照方法

- 使用同一个已准备的、版本匹配的 DSH 运行时、模型、推理强度和普通文件/命令工具。
- 上述推理强度指普通 Agent 请求。Builder 保留生产默认的最低可用推理强度，后台判断也保留其生产默认设置；实际参数逐条留证，用量照常计入。
- 单 Agent 不加载 MoA+，关闭原生创建、分支、控制子 Agent 和 workflow 四个工具入口。工具清单与实际创建数留证。
- MoA+ 使用默认配置 `{}`，按需验收，由主 Agent 自己决定是否协作；不加入专门的协作提示。
- 每次使用全新 Git 工作区、`DSH_HOME` 和 `DSH_AGENTS_HOME`；不使用个人会话、共享技能或既有项目记忆。
- 默认每题每组重复两次，共 32 次。第二次反转题目及各题两组的启动顺序。每对两组并行运行，等两组结束后才开始下一对。
- 简单题分别限时 60/90 秒，复杂题各 420 秒。两组全部 Agent 合计上限相同：64 个模型请求、500,000 个总 token。
- token 上限在请求开始和 usage 返回时检查；在途请求可能超额，实际超额量另记。超时先原生停止并清理后代；清理卡住时只结束本次启动的进程树。
- 开始前冻结题目、评分器、运行器与生产构建的哈希。所有失败保留，不重复运行到通过，不在评测过程中修改产品。

## 运行

需要 Node 24.9+、Git、已构建的 MoA+，以及与其兼容的独立 DSH 运行时。
Windows Desktop 兼容运行时应使用匹配的 Electron 可执行文件作为 `--engine`，避免原生依赖 ABI 不一致。
该引擎通过 `ELECTRON_RUN_AS_NODE=1` 运行，不打开桌面窗口。

输出目录必须全新且在仓库之外。凭据只以路径交给原生 credential provider，不复制或打印其内容。
下面路径是示例，应替换为本机准备好的位置。

```powershell
node evals/moa-vs-single/run.mjs --prepare `
  --output C:/eval-output-001 `
  --runtime C:/eval-runtime `
  --credentials C:/credentials.yaml `
  --engine 'C:/Program Files/DSH NEXT/DSH NEXT.exe'

# 启动检查不调用模型。需要先检查通过，再运行正式评测。
node evals/moa-vs-single/run.mjs --boot-check --plan C:/eval-output-001/manifest.json
node evals/moa-vs-single/run.mjs --run --plan C:/eval-output-001/manifest.json

# 根据已保存的结果重新生成报告，不调用模型。
node evals/moa-vs-single/run.mjs --report --plan C:/eval-output-001/manifest.json
```

可在准备时指定 `--provider`、`--model`、`--reasoning` 和 `--repetitions`。
`--suite basic` 默认跑原有8题，`--suite hard` 只跑2道难题，`--suite all` 跑全部。
难题可以预先设置相同的更高上限，例如两组都使用 `--max-total-tokens 1000000 --max-requests 80`；限额写入冻结计划，不能看过结果再改。本次难题每次限时600秒。基础集保留原输入与评分，以便比较修复前后效率。
每轮正式对照需要新的输出目录。不要同时从两个控制进程运行同一份计划。
`--run` 会跳过已有 `scored.json` 的运行，不会覆盖现有原始证据。

## 证据与解释

输出包含：

- `manifest.json`：固定题目、输入哈希、顺序、上限、模型及构建哈希。
- `runs/<id>/result.json`：正常/异常结束、耗时、根 Agent 首文字时间、实际工具清单、所有模型请求与用量、Agent 数量及类型。
- `runs/<id>/scored.json`：独立评分和逐项结果。
- 各运行的原生 Session、产物、stdout/stderr：便于复核失败和交付。
- `report.md`、`report.html`、`report.json`：汇总和逐题对比。

用量覆盖主 Agent、普通 Worker、验收助手和后台判断请求。每个请求只取最后一份 usage，避免重复累计。
输入、缓存读取、缓存写入、输出分开记录；reasoning 是输出子集，未上报时记未知。
usage 不完整时，已记录 token 标为下限；完整样本均值附样本数，精确用量比值只用于两边 usage 完整的配对，不能把未知消费当作零。
总 token 是用量指标；这里不按可能变化的价格折算金额。

优先比较各题质量及满分交付，再看耗时和用量。简单任务应避免不必要协作；复杂任务需要用完成结果证明协作价值。
8 类任务、每组两次属于初步产品对照，不能证明统计显著性或普遍能力提升。
同一服务的负载、跨请求缓存、只有一个模型与固定合成输入都会限制结论。
这套评测不替代桌面视觉、用户交互、长期记忆或大型真实仓库评测。

不要提交个人凭据、配置根、原始 Session、私人对话、运行目录或带个人路径的结果。
