# MoA+：目标与当前实现

MoA+ 的目标是构建一个真正的多智能体系统（Mixture of Agents），通过 Agent 之间的相互协作，把整个系统的智能能力推向下一个台阶。具体的协作机制将随设计与验证继续演进。

## 当前实现：Coordinator 与 Workers

当前版本以 DeepSeek Harness 插件的形式实现，先提供持续协调、持久化 Worker 会话、共享上下文和结果回传。在这一实现中，Coordinator 维护工作记录和共享知识，控制可持续交流的 Workers，并承担上下文管理和协调判断。项目持续使用同一个 Coordinator 会话；Agent 的内存驻留、空闲释放和恢复遵循 DSH。

## 工作记录与可复用知识

```text
.dsh/project-mode/<project-id>/
├── notes.md                 Coordinator：待办、分工、进度、阻塞、下一步
├── archived.md              Coordinator：完成或告一段落的工作与结果
└── context/
    ├── context.md           共同维护：文件路径和简短介绍组成的索引
    ├── decisions.md         可复用的决定与依据（按需创建）
    └── ...                  可复用的事实、方法和其他项目知识
```

Agent 先读 `context/context.md`，了解有哪些信息，再按当前任务需要读取正文。上下文不会在每次请求中被全量展开。Workers 把有价值、可在后续工作中复用的发现补入上下文文件，再更新索引。Coordinator 更多负责整理、合并、删除过时或重复内容，保持索引和知识库好用。双方都可以维护上下文；这是一份职责约定，不增加独占写入或额外权限限制。

新项目创建索引。旧项目在下一次实际工作时，通过当前 Agent 的原生文件系统补齐缺失索引，只读取目录元信息，不读取或覆盖已有正文。权限不足不会阻塞对话；权限和文件修改仍由 DSH 管理。

## Coordinator 的常见操作流

1. 新用户消息到达，先 list Workers，了解状态和用户对子会话的直接操作；按需 get 或读取指定窗口的 history。
2. 读取工作记录和上下文索引，判断已有 Worker 的上下文是否适合继续承担任务，或为新的责任派生 Worker。
3. 下发完整目标、必要上下文引用、约束和预期结果，再更新 notes.md。
4. 根据进展作出投递判断：steer 引导当前工作，queue 留待当前 turn 结束后处理；interrupt 停止执行，delete 从团队中移除 Worker。
5. 保持对用户输入的响应。等待时汇报进展并交还控制；Worker 每轮结束自动回传完整最后一条 AI 消息，Coordinator 随后审阅结果和证据。
6. 对具体缺口继续引导同一 Worker，必要时派生其他 Worker或请用户决定；更新工作记录，整理有复用价值的上下文。相关结果均已处理且无需继续协调时收口。

这些动作由 control_workers 统一提供，沿用 DSH 的原生会话、投递、权限与停止机制。职责提示明确日常判断和操作流，不用关键词路由、命令次数或时间阈值强迫分工。

## Worker 的职责

Worker 先读共享索引、按需获取上下文，完成其负责的调查或执行，说明具体阻塞和所需决定。任务产生的可复用知识补入共享上下文和索引；notes.md、archived.md 由 Coordinator 维护。最终 AI 消息自包含说明结果、证据、文件或产物、补充的共享知识和遗留事项，由系统自动回传。

以上是当前版本的角色职责与操作流程，为继续探索多智能体协作提供实现基础。
